# Phase 4 Windows 人工验收指南

## 准备

- 使用干净 Windows 电脑和 Phase 4 安装包。
- 准备自行申请的 OpenAI、Gemini、DeepSeek 测试 Key；真实请求可能产生少量费用。
- 准备一个 Phase 3 `.fishtongue` 项目。

## 核心步骤

1. 打开 Phase 3 项目，确认正常迁移并可保存、关闭和重新打开。
2. 不配置 AI，回归词典、语素、造词、演化和屈折。
3. 在“工具 → AI 与模型设置”分别添加三家官方服务。
4. 确认填写过的 Key 不会再次显示，只显示“已安全保存”。
5. 勾选联网说明，读取模型列表并执行连接测试。
6. 打开 AI 侧栏，确认可以直接切换已启用的服务商和模型；分别测试页面、语言和项目范围。
   在词典页面询问词条数量，确认“当前页面”能读取实际词条而不只是页面名称。
7. 检查回答下方的实际引用，启动请求后测试“停止”。
8. 让 AI 生成单个词条和语素提案，点击“填入编辑器”，确认内容进入正式新建表单；
   修改后由用户点击保存。
9. 让 AI 一次生成 10 个词条或语素，确认出现紧凑表格审核入口；直接修改字段，在首列
   把一行改为“拒绝”，再改回“接受”，确认可以恢复；最后分别保留接受和拒绝项并统一提交。
   在浅色和深色模式各打开一次，确认表格颜色与应用一致、文字清晰。确认保存项立即出现
   在当前词典或语素库，不需要切换页面。再测试一次 50 项请求。
   发送后应立即看到自己的消息；等待期间不得显示 `fishtongue-proposals` JSON，也不得永久停留在“正在回答”。
10. 让 AI 生成造词配置，确认内容进入造词配置表单，手动执行“验证并保存”。额外使用包含
    `members`、`template`、`min/max` 的兼容提案，确认应用会转换而不是崩溃。
11. 让 AI 生成演化提案，确认合法规则通过真实 Lexurgy 校验后才进入编辑器；必须再由用户
    验证并点击“验证后保存”。另让 AI 提出包含 `Feature voiced(+, -)` 的错误规则，确认应用
    在填入前阻止它，并显示错误行列。
12. 让 AI 生成屈折提案，确认 JSON 和测试词干进入屈折编辑器；必须先运行预览，再保存。
    额外测试 `{ "type": "suffix", "form": "{stem}n" }` 简写，确认转换后可以运行，
    且不再显示 `error decoding response body`。随后在同一会话要求“再生成一个不同的屈折
    提案”，确认新提案与前一个结构不同。
13. 确认每条助手回答的引用和提案紧跟在该回答下方，不会统一堆在会话底部。
14. 拒绝一个提案，确认项目数据不变；保存一个提案，确认重新打开后存在。
15. 修改目标后尝试应用旧提案，确认系统提示提案过期且不覆盖。
16. 添加一个本机 OpenAI 兼容地址，确认 HTTP 只允许回环地址。
17. 断网后确认全部非 AI 功能正常。
18. 把项目复制到另一台电脑，确认对话存在但必须重新设置 Key。
19. 删除 Provider，确认对应 Windows 凭据一同删除。
20. 卸载、重装并再次打开项目。

## 通过标准

- 项目、日志和设置文件中找不到 Key。
- AI 不能未经确认修改正式数据。
- 取消、断网、认证失败和限流均不损坏项目。
- 关闭应用后无额外进程残留。
