# FishTongue 后续产品改进要求

本文件记录已由人工验收提出、但不适合在当前缺陷修复中仓促完成的产品要求。后续阶段规划必须逐项评估，不得遗失。

## 面向语言学新手的离线帮助

- 在涉及语言学知识或规则语言的页面右上角提供统一的 `⍰` 帮助入口。
- 在 IPA、词性、语素类型、音位类别、音节模板、音变规则和屈折规则等字段旁提供字段级 `⍰`。
- 点击后使用应用内弹窗或侧栏解释“它是什么、什么时候使用、简单示例、常见错误”。
- 音变和屈折页面需要提供可复制的最小规则示例，并解释其中的符号和执行顺序。
- 帮助内容必须离线可用，支持中英文，不依赖 LLM 或网络。
- 帮助入口不能遮挡编辑区，也不能改变项目数据。

## IPA 与项目音位表联动

- 正式音位表完成后，词条 IPA 应优先通过项目现有音位表选点输入。
- 选择器需要支持音位、音节边界、重音和常用附加符号。
- 不在音位表中的字符需要明确标记；专家手工输入只能作为可选高级方式。
- 音位表变更不能静默改写已经保存的词条 IPA。

## 演化输入词典筛选

- “当前词典”默认选择当前筛选范围内的全部词条，而不是只显示不可操作的词形标签。
- 支持按词性、状态、来源和搜索文本筛选。
- 支持逐词取消或重新选择，并显示最终将运行的词数。
- 筛选只决定本次只读预览输入，不修改词典。

## 候选审核与冲突处理

- 保留已提交批次中的未接受和拒绝候选，直到用户主动删除候选列表。
- 提供全选、批量接受、批量拒绝和多选编辑。
- 冲突候选不得静默覆盖词典。提交时应汇总全部冲突，并让用户逐项选择：
  放弃候选、替换现有词条或返回手工编辑。
- “替换现有词条”必须展示差异、进入事务和撤销记录，默认不选中。
- 长文本必须自动换行，批次操作在窄窗口下仍可完整使用。

## 语素辅助识别

- 后续可由 LLM 从词形和释义中提出“可能存在的新语素”或“可能关联的已有语素”。
- LLM 只能形成候选；新增语素及词条—语素关系必须经过用户审核确认。
- 不允许 LLM 直接创建、删除或改写正式语素数据。
