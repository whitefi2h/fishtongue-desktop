# FishTongue Phase 7：分阶段开发与正式发布计划

> 计划状态：执行中。Phase 7.1 已于 2026-08-14 通过外部 Windows 人工验收并正式结项；Phase 7.2 已进入实现与自动验收阶段，尚未完成独立 Windows 人工验收，详见 `docs/phase-7-2/`。后续开发不得改写 Phase 1～7.1 已验收语义。

## 1. 为什么重新拆分

原 Phase 7 草案把数据安全、历史阶段修复、演化增强、标签、词频、JSON 导入、新手帮助和正式发布放进了同一个开发周期。它们之间存在依赖，但不是同一种工作，也不适合一次性验收。

Phase 7 现拆为七个可以独立开发、测试和结项的子阶段：

| 子阶段 | 主题 | 用户可以直接验收的结果 | 建议工作量 |
| --- | --- | --- | --- |
| Phase 7.1 | 数据安全与历史阶段收口 | 全局撤销/重做可用，阶段词典和导航正确 | 6～8 个开发工作日 |
| Phase 7.2 | 演化工作区收口 | 方案、版本、运行记录、词汇选择和后代生成可用 | 7～9 个开发工作日 |
| Phase 7.3 | 标签系统 | 可手工或经 AI 审核维护标签，并用于筛选 | 4～5 个开发工作日 |
| Phase 7.4 | 词频与概率演化 | 词频可编辑、审核、筛选，并可确定性控制演化参与 | 6～8 个开发工作日 |
| Phase 7.5 | JSON 导入与统一冲突审核 | 导入可预览、处理冲突、原子提交和完整撤销 | 4～6 个开发工作日 |
| Phase 7.6 | 离线帮助与输入体验 | 新手帮助、IPA 音位表输入和语素候选审核可用 | 5～7 个开发工作日 |
| Phase 7.7 | 发布候选与正式发布 | 入口、安装、更新、备份、恢复、许可和回归全部收口 | 5～7 个开发工作日 |

总建议工作量为 37～50 个开发工作日。该数字用于安排顺序，不作为跳过测试或压缩人工验收的理由。

## 2. Phase 7 总完成标准

只有 Phase 7.1～7.7 全部正式结项，才能宣布 Phase 7 结项：

- 每个子阶段均有独立计划、风险表、自动验收命令、人工验收指南和验收报告。
- 每个子阶段必须先通过自动测试，再通过外部 Windows 人工验收；未结项不得开始依赖它的下一阶段。
- Phase 1～6 已验收能力持续回归，不用新功能改写旧阶段的数据语义。
- 所有正式入口要么执行真实功能，要么明确显示“尚待开发”；不得保留假数据和假按钮。
- 所有批量写入、AI 提案和演化提交均先预览、再确认、后原子提交，并且可以安全撤销。
- 旧 `.fishtongue` 项目可以逐版迁移；迁移、保存或恢复失败时保留最后一个可用项目。
- 最终发布包在目标系统上可安装、启动、升级、备份、恢复和卸载，并完成许可证与再分发审计。

## 3. 全阶段共同边界

以下规则在 Phase 7 的每个子阶段都必须遵守：

- 继续使用 Tauri 2 单机、本地优先架构；基础功能不依赖账户、云服务或 LLM。
- 数据流保持 `UI → Service → Repository → Tauri SQL Plugin → SQLite`；React 页面不直接执行 SQL、读写项目文件或管理 Sidecar。
- SQLite 仍是正式项目数据的唯一权威来源，项目格式仍为 `.fishtongue`。
- AI、PanPhon 和安全脚本只能生成候选、证据或补丁，不能绕过审核直接修改正式数据。
- 内部默认状态继续存在且不可删除；启用阶段的语言不得在普通界面暴露内部默认状态。
- `no_data` 阶段继续禁止词典、音系、形态和可翻译数据。
- Lexurgy 继续由 Kotlin/JVM Sidecar 执行，不重写规则语言或音变核心。
- 新增界面沿用现有桌面设计系统，提供中英文资源，并至少适配 `1280 × 800`。
- 不把计划中的能力描述为已经完成。

Phase 7 不包含云同步、多人协作、移动端、多窗口编辑、自动祖语重构、自动谱系推断或 Morfessor 自动切分。

## 4. 数据库版本规划

真实仓库当前已经包含 Schema v15，因此 Phase 7 从 v16 开始。不得修改已经发布或已被项目使用的旧迁移文件。

| Schema | 所属阶段 | 计划用途 |
| --- | --- | --- |
| v16 | Phase 7.1 | 项目操作日志、撤销/重做及阶段词典覆盖所需数据 |
| v17 | Phase 7.2 | 演化方案、版本、运行、追踪、输入快照、分支和后代生成 |
| v18 | Phase 7.3 | 标签、词条标签关系和 AI 标签审核批次 |
| v19 | Phase 7.4 | 词频、阶段覆盖、AI 词频审核批次和概率快照 |
| v20 | Phase 7.5～7.6 | 仅在导入审核或语素候选确需持久化新结构时使用 |

v20 不是必须产生的空迁移。实施前必须先确认现有审核批次和命令模型不能安全复用，才允许增加新表。

每次 Schema 变更都必须测试：新项目、从 v1～当前版本逐步升级、迁移中断、重复打开、备份恢复及旧项目继续编辑。

## 5. Phase 7.1：数据安全与历史阶段收口

### 目标

先建立后续功能共同依赖的安全写入和可恢复基础，并修复当前阶段词典与导航问题。本阶段不引入标签、词频或新演化模型。

### 开发内容

1. 建立实名“功能入口清单”，逐项记录入口位置、当前状态、后端连接、保留/实现/移除决定和验收方式。原草案中没有定义含义的 D1～D13 编号不再作为验收依据。
2. 实现项目级操作日志与全局撤销/重做：
   - 支持编辑菜单、`Ctrl+Z` 和 `Ctrl+Y`；
   - 覆盖现有词典、语素、造词审核、阶段、历史事件、语言关系、词源关系、音系和借词关系写入；
   - 多对象操作作为一个原子步骤撤销；
   - 记录对象版本和用户可读摘要，数据已经被后续修改时阻止危险撤销；
   - 新操作后清空重做栈，最多保留最近 100 项，关闭并重开项目后仍可使用。
3. 明确快捷键优先级：光标位于文本框或 CodeMirror 时优先撤销文字编辑；不在文字编辑环境时才撤销项目数据操作。
4. 修复阶段词典与导航：
   - 启用阶段后进入最近使用的可见阶段；
   - 普通导航、路径栏和选择器隐藏内部默认状态；
   - 历史阶段词条可编辑，修改形成阶段覆盖，不修改来源阶段；
   - 继承词条显示来源阶段和覆盖状态；
   - 跨语言跳转和返回操作恢复原页面、阶段、筛选和滚动位置。
5. 所有后续 Phase 7 写操作必须接入同一命令与撤销协议，不允许各自实现互不兼容的“撤销”。

### 结项门槛

- 新旧项目都能安全迁移至 v16。
- 重启项目后仍可撤销和重做；冲突时不会覆盖后来的修改。
- 历史阶段编辑只产生本阶段覆盖，来源数据不变。
- 内部默认状态不可见，`no_data` 限制不回归。
- 建立 `npm run verify:phase7-1`，并通过外部 Windows 人工验收。

## 6. Phase 7.2：演化工作区收口

### 目标

把已有音变能力整理为可保存、可复现、可追踪并能安全生成语言阶段或后代语言的正式工作流。

### 开发内容

1. 规则和测试词在最后一次变更 3 秒后自动保存；保存失败时保留上一个可用版本并明确提示。
2. 支持多个命名方案、复制、重命名、版本历史和恢复旧版本。
3. 每次运行保存方案版本、来源阶段、输入快照、结果、错误、中间阶段和逐规则追踪。
4. 正式启用“阶段与分支”和“历史记录”页面。
5. 正式词典输入支持搜索词形/释义，并按词性、状态和来源筛选；支持逐词选择、当前结果全选、清空、反选及切换筛选后保留已选词。
6. 运行前显示最终词数和来源阶段；测试词仍独立运行，不混入正式词典提交。
7. 演化结果可以原子提交到同一语言的新历史阶段、现有方言或新建后代语言。
8. 新建后代语言时，在同一事务内创建语言、初始阶段、完整词典和继承关系；失败时不留下半成品。

### 结项门槛

- 新旧项目安全迁移至 v17。
- 同一方案版本和输入可以重现相同运行结果与追踪记录。
- 筛选、选择和提交不会修改来源词典。
- 新阶段、方言和后代语言提交均可作为一个项目操作撤销。
- 建立 `npm run verify:phase7-2`，其中包含 `verify:phase7-1` 回归，并通过外部 Windows 人工验收。

## 7. Phase 7.3：标签系统

### 目标

建立独立于词性和词义的领域标签，用于组织词典，并连通语言接触与演化选择。

### 开发内容

1. 在词条详情中创建、添加、移除、重命名和删除标签。
2. 删除或合并标签前显示受影响词条；操作原子执行并可撤销。
3. 词典支持单标签和多标签组合筛选。
4. 语言接触来源词选择器和演化词汇选择器支持标签筛选。
5. AI 可以扫描无标签词条或用户指定范围，但只能产生独立的标签审核批次。
6. 审核界面支持修改名称、合并同义标签、接受、拒绝和批量选择；避免过细、重复或只适用于单个词的标签。
7. 标签用于“农业”“经济”“宗教”等领域分类，不替代词性、Sense 或语素。

### 结项门槛

- 新旧项目安全迁移至 v18。
- 手工标签与 AI 标签审核互不绕过正式保存流程。
- 词典、语言接触和演化页面得到相同的标签筛选结果。
- AI 未配置、断网或输出非法时，手工标签功能仍完整可用。
- 建立 `npm run verify:phase7-3`，包含此前子阶段回归，并通过外部 Windows 人工验收。

## 8. Phase 7.4：词频与确定性概率演化

### 目标

加入语言内部的相对使用频率，并允许用户把词频映射为“本次整套演化是否作用于该词”的可复现概率。

### 词频定义

```ts
usageFrequency: number | null;
usageFrequencySource: "manual" | "ai_reviewed" | "imported" | null;
usageFrequencyUpdatedAt: string | null;
```

- 合法范围为 `0–1`；`null` 表示未知，不能用 `0` 代替未知。
- 词频是单一语言内部的相对日常使用程度，不要求所有词频之和为 `1`。
- 输入最多保留四位小数；列表通常显示两位，编辑时保留原精度。
- 基础值从内部默认状态继承，历史阶段可以覆盖；覆盖不得修改来源状态。
- UI 明确显示“继承”“手工”“AI 审核”“导入”等来源。

### 开发内容

1. 词条详情可编辑词频；三栏词典可显示词频列，并按范围、未知状态排序和筛选。
2. 语言接触和演化选择器支持词频范围筛选；可与词性、状态、来源和标签组合。
3. AI 词频审核与标签审核完全分开。默认只扫描空值；重新估计已有值必须由用户主动开启。
4. AI 按语言和阶段分别估计，输出建议值、置信度和理由；非法值进入错误状态，不自动修正或保存。
5. 概率高级设置默认关闭；关闭时全部选中词都运行演化。首次开启使用 `0–1 → 100%`，不改变旧行为。
6. 概率区间必须无重叠且完整覆盖 `0–1`；未知词频默认 100%，用户可以修改。
7. 每个词对整套方案只抽样一次：命中则运行完整 Lexurgy 规则链，未命中则保持原形。
8. 使用 `SplitMix64 v1`、十进制种子、方案版本、来源阶段和词条 UUID 生成稳定抽样；结果不受列表顺序和电脑影响。
9. 用户可以对单个词选择“按概率”“强制演化”或“保持原形”。未演化的词仍完整进入目标阶段或后代语言。
10. 运行历史保存词频快照、区间概率、抽样值、决定和算法版本。
11. AI 只能提出 `lexeme_frequency.review` 或 `evolution_frequency_policy.suggest`，不能直接保存词频、概率方案或运行演化。

### 结项门槛

- 新旧项目安全迁移至 v19。
- `0`、`1`、四位小数、空值和非法输入的行为都有自动测试。
- 相同输入和种子在不同排序与不同电脑上产生相同参与集合。
- 关闭高级设置时与 Phase 7.2 行为一致；未参与演化的词不会丢失。
- 词频覆盖、AI 批量提交和概率方案修改均可安全撤销。
- 建立 `npm run verify:phase7-4`，包含此前子阶段回归，并通过外部 Windows 人工验收。

## 9. Phase 7.5：JSON 导入与统一冲突审核

### 目标

提供可理解、可预览、不会静默覆盖数据的词条导入，并统一改善现有批量候选的审核和冲突处理。

### 开发内容

1. 提供中英文 JSON 模板、字段说明、复制和下载入口。
2. 支持词形、IPA、词性、状态、来源、备注、多个 Sense、标签和可选词频；缺省词频保持未知。
3. 导入前显示统计摘要、逐项预览、错误项、重复词形和将创建的标签。
4. 缺少词形、空 Sense、非法词频或错误结构阻止提交，并指出具体位置和修改方法。
5. 冲突项支持“跳过”“返回修改”“替换现有词条”；替换默认不选中，必须先看差异。
6. 整次导入使用一个事务和一个撤销步骤；任何一项提交失败都不得留下部分导入。
7. 统一现有 AI、造词、演化和导入候选的批量审核交互：保留未接受和拒绝候选，支持全选、批量接受/拒绝和多选编辑。
8. 提交时一次性汇总全部冲突，不逐个弹出打断用户；长文本自动换行，窄窗口下操作仍完整可见。

### 结项门槛

- 合法模板可完整导入，错误文件不会修改正式数据。
- 标签、词频、多个 Sense 和来源信息导入后正确显示。
- 替换现有词条会显示差异、原子提交，并能完整撤销。
- 已提交批次中的未接受和拒绝候选不会自动消失。
- 建立 `npm run verify:phase7-5`，包含此前子阶段回归，并通过外部 Windows 人工验收。

## 10. Phase 7.6：离线帮助与输入体验

### 目标

让没有语言学和规则语言基础的用户也能理解关键字段，并减少 IPA 与语素录入错误。

### 开发内容

1. 在需要语言学知识的页面提供统一 `⍰` 帮助入口；字段级帮助解释“它是什么、何时使用、简单示例、常见错误”。
2. 帮助覆盖 IPA、词性、语素类型、音位类别、音节模板、音变规则和屈折规则；音变与屈折提供可复制的最小示例。
3. 帮助内容内置于应用，支持中英文，不依赖网络或 LLM，不修改项目数据。
4. 词条 IPA 优先通过当前项目的正式音位表选点输入，并支持音节边界、重音和常用附加符号。
5. 明确标记不在音位表中的字符；专家手工输入保留为可选高级方式。音位表变化不得静默改写已有 IPA。
6. 可选 LLM 可以从词形和释义提出“可能的新语素”或“可能关联的已有语素”，但只形成独立候选。
7. 新增语素及词条—语素关系必须经过用户审核；LLM 不得直接创建、删除或改写正式语素。

### 结项门槛

- 无网络、无 LLM 时所有帮助与音位表输入都可使用。
- 中英文帮助内容完整，键盘可访问，不遮挡主要编辑区。
- 非音位表字符只提示、不篡改；修改音位表不会改变既有词条。
- 语素候选在拒绝或未审核时不写入正式数据，接受后可撤销。
- 建立 `npm run verify:phase7-6`，包含此前子阶段回归，并通过外部 Windows 人工验收。

## 11. Phase 7.7：发布候选与正式发布

### 目标

停止增加产品功能，集中处理入口、升级、恢复、打包、许可证和全量回归，形成可交付给普通用户的正式版本。

### 开发内容

1. 复查 Phase 7.1 的实名入口清单：已实现入口连接真实功能；延期入口统一显示“尚待开发”和简短说明；废弃入口及不可达代码才允许移除。
2. 锁定首发平台矩阵：Windows x64 为必须验收目标；macOS、Linux 是否作为同版发布目标，必须根据真实构建机、Sidecar 资产和签名条件作出书面决定，不能以“理论可构建”代替验收。
3. 验证安装、升级、卸载、最近项目、项目备份、项目恢复、迁移失败恢复和损坏项目保护。
4. 验证应用与 Sidecar 的版本匹配、健康检查、超时、取消、崩溃清理和日志脱敏。
5. 完成 NSIS、Sidecar、最小 JRE、Python/PanPhon、数据集、字体和第三方依赖的许可证、署名、SBOM、SHA-256 与再分发审计。
6. 明确自动更新策略。若本次不交付自动更新，必须在产品中给出真实版本与手动升级说明，不能保留可执行的假更新按钮。
7. 冻结 Schema 和项目格式，完成从所有历史版本升级到最终版本的真实样本测试。
8. 完成 Phase 1～6 与 Phase 7.1～7.6 的全量回归、安装包测试和外部人工验收。

### 结项门槛

- 建立 `npm run verify:phase7` 作为最终总验收命令。
- 自动验收至少覆盖 Jest、Cypress、SQLite 迁移、Rust、Python Analysis Sidecar、Lexurgy 引擎、静态导出、安装包、SBOM、许可证和校验值。
- 在干净的 Windows x64 电脑上完成安装、升级、运行、备份、恢复、卸载及主要业务流程验收。
- 发布说明准确列出新增能力、迁移要求、已知限制和延期功能。
- 外部人工验收通过后才创建正式发布标签并宣布 Phase 7 结项。

## 12. 阶段依赖与推进规则

```text
Phase 6 已结项
  → 7.1 数据安全与阶段修复
  → 7.2 演化工作区
  → 7.3 标签
  → 7.4 词频与概率演化
  → 7.5 JSON 导入与冲突审核
  → 7.6 离线帮助与输入体验
  → 7.7 发布候选
  → Phase 7 正式结项
```

- 7.2 依赖 7.1 的命令和撤销协议。
- 7.3 的标签是 7.4 组合筛选和 7.5 完整 JSON 格式的前置条件。
- 7.4 必须在 7.2 的运行快照和确定性模型上增加概率，不得另建一套演化执行器。
- 7.5 必须等标签与词频字段稳定后再锁定导入格式。
- 7.6 可以在 7.5 结项后实施；如果希望并行，只允许处理纯帮助文案，不能提前改动未稳定的数据界面。
- 7.7 开始后进入功能冻结；只修缺陷、兼容性、可访问性、文档和发布问题。

## 13. 每个子阶段的固定交付物

每个 Phase 7.x 都必须留下以下可供人类阅读和复查的成果：

1. 开发计划或执行清单；
2. 风险登记表；
3. 数据迁移说明及旧项目兼容证据；
4. 自动验收脚本和测试结果；
5. Windows 人工验收指南；
6. 验收报告，明确“已验证”“未验证”“已知风险”；
7. 用户可理解的变更说明和必要截图。

如果某项未通过，应只保持当前子阶段为开发中，不影响已经正式结项的 Phase 1～6，也不得用“部分完成”宣布子阶段结项。

## 14. 原计划需求去向

| 原计划内容 | 新阶段 |
| --- | --- |
| 全局撤销/重做、阶段词典、导航修复、入口审计 | Phase 7.1 |
