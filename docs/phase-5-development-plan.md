# FishTongue Phase 5：历史阶段、谱系、方言、事件与词源

## 目标

Phase 5 把语言从单一“当前状态”扩展为可追踪的历史系统，同时保证旧数据不被覆盖：

- 每门语言始终拥有一个隐藏的内部默认状态。
- 用户可创建自由命名的历史阶段和轻量方言。
- 阶段的时间顺序与数据继承关系分开保存。
- 无记录阶段只保存背景和关系，不伪造语言数据。
- 项目允许多个根语言；主要遗传父级与语言接触分别建模。
- 历史事件可关联语言与阶段。
- 词条可记录继承、借入、同源、派生和仿译关系。
- 正向音变先生成审核批次，确认后才创建目标阶段数据。

项目数据库由 v7 原子迁移至 v8；人工验收修复迁移 v9 保证阶段及其上下文原子保存。
项目容器格式保持 v1。

## 锁定边界

- `LanguageStage.kind`：`internal_default | historical_stage | lightweight_dialect`。
- `documentationStatus`：`recorded | partial | unrecorded | reconstructed`。
- `storageMode`：`inherited_delta | independent_snapshot | no_data`。
- 时间父级只表达先后；数据基础只表达继承，两者不得混用。
- 一个语言最多拥有一个主要遗传父级；接触关系不占用该位置。
- 不实现自动逆向重构、地图、借词自动适配、完整音系快照或跨项目谱系。

## 执行任务

### P5-00 基线封存

- 重跑 `npm run verify:phase4`。
- 记录安装包哈希和外部验收结论。
- 合并 Phase 4，创建 `phase-4.0.1` 标签。
- 创建 `codex/phase-5-history-genealogy` 分支。
- 版本升级为 `0.5.0-phase.5`。

### P5-01 领域模型与架构边界

- 建立 Stage、Relation、Event、Etymology 和有效状态模型。
- 定义 Repository 与 `Phase5Application`。
- UI 只调用应用层接口。
- 增加继承循环、谱系循环和无记录数据保护。

### P5-02 Schema v8 与迁移

- 新增阶段、上下文、差异、语言关系、事件、词源和演化审核表。
- 为旧语言自动创建内部默认状态。
- 新建语言由数据库触发器自动创建默认状态。
- 事件及参与者通过命令表原子保存。
- 验证外键、JSON、级联、唯一父级和失败回滚。

人工验收补充：

- Schema v9 新增阶段写入命令表，将阶段、背景、证据和来源作为一次事务保存。
- 新建阶段的位置与既有位置冲突时，由数据库安全分配下一个位置。
- 保存任一部分失败时，阶段和上下文均不落库。

### P5-03 有效状态解析器

- 从内部默认状态加载正式词典、语素、演化、屈折与造词配置。
- 沿 `dataBaseStageId` 递归解析继承。
- 按顺序应用 replace、merge 和 remove 差异。
- 检测循环和过深继承。
- 无记录阶段返回空语言数据及明确警告。

### P5-04 阶段与方言工作区

- 接入真实项目阶段列表、编辑器和上下文记录。
- 支持资料状态、数据方式、年代、时间父级和数据基础。
- 轻量方言固定使用继承加差异。
- 内部默认状态不可删除。

### P5-05 语言谱系

- 支持多个根语言。
- 支持主要继承、接触和方言关系。
- 保存前检测循环。
- 拖动和视觉排列不得直接修改正式关系。

### P5-06 历史事件

- 支持迁徙、接触、分化、标准化、政治、文化及其他事件。
- 事件可关联多个语言和阶段。
- 事件与参与者同一事务保存。

### P5-07 词源关系

- 支持继承、借词、同源、派生、仿译和未知关系。
- 来源词可缺失，但必须保留来源形式。
- 删除来源词只解除引用，不删除目标词。

### P5-08 正向演化审核

- 从来源阶段读取有效词典并调用现有 Lexurgy。
- 保存规则、输入和结果快照。
- 用户逐项接受、拒绝或编辑。
- 提交只创建目标阶段差异，不覆盖来源阶段。
- 失败、取消或保存失败不得留下半个批次。

### P5-09 AI 上下文

- 增加阶段、关系、事件和词源只读工具。
- AI 仍默认只读；阶段和关系修改必须形成提案。
- 项目文本不得改变工具白名单或安全范围。

### P5-10 自动验收

`npm run verify:phase5` 执行：

- Jest 领域、解析器、循环和服务测试。
- Cypress 阶段、方言、谱系、事件、词源及演化审核。
- SQLite v8 迁移、约束、事务和失败恢复。
- Phase 2～4 回归、静态导出和架构审计。
- Rust 测试、检查、引擎契约和 NSIS 构建。
- 安装包版本、内容、许可证和 SHA-256 审计。

## 人工验收

1. 打开 Phase 4 项目并确认原词典与规则仍在。
2. 确认每门语言存在内部默认状态但界面不强制显示阶段。
3. 创建有记录、部分记录、无记录和重构阶段。
4. 验证无记录阶段无法写入语言数据。
5. 建立继承链并确认来源状态不被覆盖。
6. 创建轻量方言并验证继承加差异。
7. 建立多个根语言、主要父级和接触关系。
8. 尝试创建循环谱系并确认被拒绝。
9. 创建历史事件并关联语言与阶段。
10. 为词条建立继承和借词关系。
11. 用 Lexurgy 创建下一阶段审核批次，处理冲突后提交。
12. 关闭重开、另存为、断网和重装后复核全部数据。
