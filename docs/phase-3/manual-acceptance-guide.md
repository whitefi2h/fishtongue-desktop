# FishTongue Phase 3 外部人工验收

使用没有安装系统 Java 的 Windows x64 电脑。建议复制一份 Phase 2 项目作为测试文件。

修复包：`FishTongue_0.3.0-phase.3.2_x64-setup.exe`

SHA-256：`AE842CF81D2BB66EEDF3BC7C0288E8D532C3BCA9E0E5C764D8B94ED5AE3FA45F`

逐项验收：

1. 校验安装包 SHA-256，安装 FishTongue，并确认电脑没有预装 Java。
2. 打开 Phase 2 或首轮 Phase 3 测试项目，正常保存后重新打开，确认迁移到数据库版本 5 且没有丢失旧数据。
3. 新建词条，填写词形、IPA、词性、状态、来源和备注，并添加至少两个独立词义。
4. 关闭项目并重新打开，确认词条及多个词义全部保留。
5. 创建至少三种不同类型的语素，把它们关联到词条并调整顺序。
6. 建立包含多字符音位的造词配置，保存后重新打开确认配置仍在。
7. 选择 Swadesh 100，使用固定种子生成候选，并记录前十项结果。
8. 使用相同配置、种子和概念顺序再次生成，确认结果逐项相同。
9. 只修改种子再次生成，确认结果发生变化且旧审核批次没有被覆盖。
10. 分别测试重复、禁配和无解配置，确认显示错误且词典没有新增词条。
11. 在同一批次中接受、拒绝并手工修改不同候选。
12. 关闭项目并重新打开，确认审核进度和修改后的候选保留。
13. 提交接受候选，确认只有接受项进入词典，拒绝和待审核项没有进入。
14. 选择源词和语素进行批量派生，处理重复或非法形式后提交。
15. 撤销最近一次 Phase 3 批量提交，确认相关词条被移除、候选回到待审核。
16. 再次提交后手工修改其中一个词条，然后尝试撤销，确认整批撤销被安全阻止。
17. 启动较长生成任务并取消；再手动结束 Lexurgy 进程，确认项目数据不受损且引擎可重新启动。
18. 分别运行一次真实音变验证/预览和屈折预览，确认 Phase 2 能力正常。
19. 退出 FishTongue，在任务管理器确认没有 FishTongue 所属的 Java/Lexurgy 进程残留。
20. 保持断网，卸载并重装应用，再次打开原项目，确认词典、语素、配置和审核批次仍在。

任何一步出现数据丢失、半批词条、无法退出或残留进程，都应停止验收并记录为严重问题。

## 第 5 项：语素关联和顺序

1. 打开“形态学 → 语素库”。
2. 创建词根 `mar`（含义：海）和后缀 `-in`（含义：相关事物），分别点击“保存语素”。
3. 打开“词典”，选择一个已有词条；若没有，先创建并保存词条 `marin`。
4. 在右侧详情内找到“形态组成”。默认应只看到“尚未关联语素”的提示，不应直接列出全部语素。
5. 在“形态组成”的搜索框输入 `mar`，勾选 `mar`；再搜索 `in`，勾选 `-in`。
6. 选中后，上方会出现编号列表。使用“上移/下移”调整为 `mar` 在前、`-in` 在后。
7. 点击详情标题区的“保存”，关闭并重新打开项目。
8. 再次选择该词条，确认两个语素及顺序仍然存在，且列表默认只显示该词条已关联语素。

## 第 14 项：批量派生任务

1. 在词典中准备两个源词：`mar`（海）和 `tal`（土地）。
2. 在“形态学 → 语素库”创建前缀 `na`，含义填“相关的人”。
3. 将组合方式设为“模板”，模板填写 `{morpheme}{stem}`，适用词性填写“名词”，并保存。
4. 打开“形态学 → 批量派生”，选择语素 `na`。
5. 在“源词”区域确认默认不直接铺开全部词条；搜索 `mar` 后勾选 `mar`，搜索 `tal` 后勾选 `tal`。
6. 点击“创建派生审核批次”。
7. 页面应自动转到“词典 → 候选审核”，并看到 `namar` 和 `natal`。接受其中一个、
   拒绝另一个，再点击“提交本次已接受项”。
8. 回到词典，确认只有接受的派生词进入词典。
9. 可预先手工创建 `namar` 后重复任务，确认系统标出重复冲突且不会静默覆盖。

## 第 17 项：长任务取消

本项已由外部验收决定跳过，不再作为 Phase 3 结项门槛。此前极端配置返回
`NO_LEGAL_CANDIDATE` 属于正确的安全终止，不代表取消能力失效。

自动化仍使用可控的慢速引擎替身验证取消提示、无半批次、可再次生成以及项目数据不受影响。
