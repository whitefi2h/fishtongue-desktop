# FishTongue Phase 1.5 UI/UX 设计方案

**文档版本：** v1.0  
**适用阶段：** Phase 1.5  
**文档性质：** 桌面端 UI/UX 重构与交互设计需求  
**目标读者：** UI/UX 设计师、前端工程师、产品与开发负责人  

---

## 1. 项目背景

FishTongue 是一款面向人造语言创作者的本地桌面应用，基于 Lexurgy、Lexurgy App、PolyGlot 等现有开源项目继续开发。

Phase 1 已完成桌面应用基础、项目创建与本地数据保存，但当前界面仍明显保留网页式设计特征：

- 使用大标题、居中单列和大面积留白；
- 桌面窗口空间利用率低；
- 浏览器原生弹窗破坏桌面应用体验；
- 项目、语言、阶段与功能模块的层级不明确；
- 缺少稳定的桌面菜单、导航、工作区、状态栏与上下文工具栏；
- 后续功能较多，现有信息架构无法承载。

Phase 1.5 的目标不是简单更换配色，而是将现有界面重构为一套真正符合桌面软件使用习惯的交互系统。

---

## 2. Phase 1.5 核心目标

1. 建立完整、可扩展的信息架构。
2. 将应用从“网页装进桌面壳”重构为真正的桌面工作软件。
3. 重做欢迎页、项目创建、项目主页和语言工作区。
4. 建立统一的中英文设计组件库。
5. 为阶段、方言、演化、词源、AI 和开发者工具建立稳定入口。
6. 保留现有 Lexurgy 规则编辑能力，并使其融入 FishTongue 的整体交互。
7. 所有 AI 或批量操作继续遵守“系统提出、用户审核、用户提交”的原则。
8. 为尚未进入首版的功能保留明确但不误导用户的入口。

---

## 3. 设计定位

### 3.1 视觉方向

整体结构参考 PolyGlot：

- 左侧存在稳定、明确的功能导航；
- 所有功能围绕当前项目与当前语言组织；
- 词典、语音学、形态学等模块可以快速切换；
- 信息密度高于普通网页。

视觉风格不沿用 PolyGlot 的旧式界面，应采用：

- 现代扁平化设计；
- 中高信息密度；
- 轻量圆角；
- 以边框、分区、背景层级代替大面积阴影；
- 中性色为主，搭配单一主强调色；
- 表格、属性面板、树形结构和分栏编辑优先；
- 不使用营销页式巨型标题；
- 不使用浏览器原生弹窗。

### 3.2 桌面应用设计原则

| 网页式设计 | FishTongue 桌面设计 |
|---|---|
| 巨型欢迎标题 | 紧凑欢迎区与功能入口 |
| 居中单列页面 | 全窗口多栏工作区 |
| 浏览器原生弹窗 | 应用内模态框或原生文件对话框 |
| 页面间频繁跳转 | 固定导航与局部内容切换 |
| 大卡片堆叠 | 表格、面板、工具栏与属性栏 |
| 所有操作依赖页面按钮 | 菜单、快捷键、右键菜单与工具栏共同承担 |

## 4. 全局桌面框架

建议采用以下固定结构：

```text
┌──────────────────────────────────────────────────────────┐
│ 原生标题栏 / 自定义窗口标题栏                            │
├──────────────────────────────────────────────────────────┤
│ 文件  编辑  视图  项目  语言  工具  帮助                 │
├──────────────────────────────────────────────────────────┤
│ 当前页面上下文工具栏                                     │
├──────────────┬─────────────────────────────┬─────────────┤
│ 左侧导航栏    │ 主工作区                    │ AI 侧边栏    │
│ 可折叠        │                             │ 可折叠       │
├──────────────┴─────────────────────────────┴─────────────┤
│ 状态栏                                                   │
└──────────────────────────────────────────────────────────┘
```

### 4.1 左侧导航栏

建议宽度为 220–260 px，可折叠为仅图标模式。

#### 项目层级

```text
项目名称
├── 项目主页
├── 所有语言
├── 语言谱系
├── 历史事件
└── 项目设置
```

地图视图仅预留扩展位，不进入 Phase 1.5 正式功能。

#### 语言层级

```text
项目主页

语言名称
├── 概览
├── 基本属性
├── 语音学
├── 形态学
├── 词典
├── 书写系统
├── 演化
├── 语言接触
└── 辅助翻译
```

项目层级与语言层级不得在左侧导航中同时完整展开：

- 项目页面只显示项目层级，不显示当前语言卡片或语言模块；
- 进入某种语言后，项目层级只保留“项目主页”返回入口，再显示当前语言和语言模块；
- 项目级页面不继承上一次选择的语言或阶段作为页面上下文；
- 空间不足且 AI 侧栏打开时，导航自动折叠为 48 px 图标轨道，并隐藏原生滚动条视觉。
- 导航展开宽度默认 220 px；受限宽度下采用覆盖式展开，不挤压主工作区。
- 受限高度下使用紧凑垂直密度，确保导航末项、AI 提案卡和输入区保持可达。

#### 上下文路径

上下文工具栏必须反映当前层级：

```text
项目页面：项目 → 当前页面
语言页面：项目 → 语言 → 阶段或默认状态 → 当前模块
```

- 点击项目名称返回项目主页；
- 工具栏右侧提供页面级“返回上一页”按钮，并支持 `Alt+左方向键`；没有历史时按钮禁用；
- 语言节点可以切换语言；
- 阶段节点可以切换当前语言的阶段；未启用阶段时显示“默认状态”；
- 切换语言时使用该语言的首个可用阶段，若没有显式阶段则使用内部默认状态；
- 当前页面节点只用于定位，不重复承担切换功能。

### 4.2 主工作区

主要采用以下布局：

- 表格 + 详情面板；
- 左右分栏；
- 顶部标签页；
- 属性分组；
- 可拖动调整宽度的面板；
- 支持多选和批量操作。

不同模块应使用统一的页面骨架，不应各自形成完全不同的视觉体系。

### 4.3 AI 侧边栏

- 默认折叠；
- 宽度随窗口在 260–360 px 之间自动缩放；
- 低于 340 px 时，上下文范围从三列重排为两列；
- 内部文字、提案卡和输入区必须依据侧栏自身宽度换行，不得横向裁切；
- 支持拖动调整；
- 支持固定和关闭；
- 顶部显示当前上下文；
- 涉及修改时必须生成提案卡片，而不是直接写入数据。

### 4.4 状态栏

底部常驻，显示：

```text
保存状态｜当前项目路径｜当前层级上下文｜验证问题数量｜AI 连接状态
```

项目页面显示“项目级视图”和项目问题总数；语言页面显示当前语言、阶段和该语言的问题数。

示例：

```text
已保存 · D:\Languages\WorldA.fishtongue
当前：阿兰语 / 诸王时期
3 项规则警告 · AI 已连接
```

## 5. 启动逻辑与欢迎页

### 5.1 启动逻辑

#### 从未创建过项目

进入首次使用欢迎页。

#### 已有最近项目

默认打开用户上次正常退出时使用的项目。

设置中允许用户选择：

- 启动时打开上次项目；
- 启动时显示欢迎页。

#### 上次项目无法打开

可能原因包括：

- 文件被移动；
- 文件被删除；
- 项目格式过旧；
- 上次运行异常退出。

应显示恢复页面：

```text
无法打开上次项目

[重新定位文件] [打开其他项目] [新建项目]
```

不得停留在空白页或直接报技术错误。

### 5.2 欢迎页

欢迎页应紧凑，不使用大尺寸宣传文案。

建议结构：

```text
FishTongue

创建或打开一个语言项目

[快速开始] [从零构建]
[打开项目] [导入项目]

最近项目
项目 A
项目 B
项目 C
```

“导入项目”属于文件操作，不与语言创建方式混为同一概念。

## 6. 新建项目与创建第一门语言

### 6.1 项目信息

字段包括：

- 项目名称；
- 项目说明；
- 保存位置；
- 默认界面语言；
- 是否自动保存。

创建项目后，进入第一门语言的创建流程。

### 6.2 语言创建方式

#### A. 快速开始

说明：

> 从现实语言的部分或全部规则开始，通过修改、音变和词汇生成建立新语言。

流程：

```text
选择现实语言模板
→ 选择参考维度
→ 设置参考强度
→ 预览音系和基础规则
→ 创建语言
→ 可选生成基础词汇
```

可分别参考：

- 辅音；
- 元音；
- 声调；
- 音节结构；
- 音位配列；
- 重音；
- 拼写；
- 形态类型。

允许混合不同现实语言的不同维度。

#### B. 从零构建

说明：

> 创建一门空白语言，并逐步设置音系、形态和书写规则。

初始向导仅填写：

- 语言名称；
- 基础说明；
- 是否使用 IPA；
- 是否建立空白音系；
- 是否使用基础模板。

不要求用户在向导中一次性完成全部语言规则。

#### C. 打开或导入项目

用于：

- 打开 `.fishtongue` 项目；
- 导入旧版本项目；
- 导入受支持的交换格式。

### 6.3 LLM 预设建议

不再设置独立的“反推语言”创建模式。

在创建语言页面中提供一个 AI 预设入口：

> 根据我的已有词汇提出设计建议

用户可以粘贴或导入：

- 少量词汇；
- 词汇及释义；
- 简短句子；
- 句子翻译；
- 已知发音。

LLM 可以提出：

- 可能的音位；
- 可能的音节结构；
- 重复出现的词素；
- 可能的构词规律；
- 多种替代解释；
- 数据不足说明。

这些结果仅作为讨论和提案：

```text
LLM 建议
→ 用户查看
→ 选择部分内容
→ 应用到创建草稿
→ 用户修改
→ 用户确认创建
```

界面必须明确提示：

> 这些内容基于有限材料推测，并不代表唯一或确定的语言学分析。

## 7. 项目主页

打开项目后，默认进入项目主页。

### 7.1 普通视图

采用高信息密度列表或紧凑卡片列表。

每门语言至少显示：

- 名称；
- 当前状态；
- 所属语系；
- 使用年代；
- 使用地区；
- 词条数量；
- 是否启用阶段系统；
- 当前活动阶段；
- 完成度；
- 最后修改时间；
- 警告数量。

支持筛选：

- 活语言 / 死语言；
- 祖源关系；
- 语系；
- 地区；
- 年代；
- 是否拥有词典；
- 是否存在待处理警告；
- 自定义标签。

顶部操作：

```text
[新建语言] [导入语言] [筛选] [排序] [搜索]
```

### 7.2 语言谱系视图

界面名称使用：

> **语言谱系**

点亮条件：

> 项目中存在至少一条明确的语言继承或分支关系。

节点支持：

- 单击选择，双击进入语言；
- 展开或收起该语言的历史阶段；
- 查看父语言和子语言；
- 查看节点警告。

画布操作：

```text
鼠标滚轮：以指针位置为中心缩放
Ctrl + 鼠标左键拖动：平移画布
适合窗口：重置为完整可见范围
```

- 谱系页是只读视图，不在画布上创建、修改或删除关系。
- 语言关系统一在“语言 → 基本属性 → 语言关系”中维护。
- 默认只显示主要继承关系；接触与方言关系通过独立图层开关叠加。
- 项目允许多个根语言；循环或无效引用必须在保存关系时阻止。
- 操作说明收纳在页面“？”帮助中，不占用主画布空间。

## 8. Language、LanguageStage 与方言模型

### 8.1 Language 可以没有用户可见阶段

用户可以完全不使用阶段系统。

#### 单一状态模式

```text
阿兰语
├── 语音学
├── 形态学
├── 词典
└── 书写系统
```

界面不显示阶段选择器。

#### 历史阶段模式

用户主动启用后显示：

```text
阿兰语
├── 圣典时代
├── 诸王时期
└── 现代通用语
```

技术上，未启用阶段系统的 Language 仍使用一个内部默认状态保存语言数据，但该状态：

- 不显示为历史阶段；
- 不要求填写名称和年代；
- 不出现在时间轴；
- 仅作为内部数据容器。

用户以后启用阶段系统时，可以：

- 将当前状态命名为某个阶段；
- 以当前状态为基础创建更早或更晚的阶段。

### 8.2 阶段名称

每个阶段均由用户自由命名，例如：

- 圣典时代；
- 诸王时期；
- 北迁后期；
- 第一次标准化时期；
- 现代通用语。

系统可以建议“早期、古典、中古、晚期、现代”等名称，但不得强制。

阶段顺序由以下信息决定：

- 起止年代；
- 前后继承关系；
- 用户指定顺序。

不得根据名称自动推断先后。

### 8.3 阶段基本字段

- 自定义名称；
- 可选简称；
- 起止年代；
- 排列顺序；
- 资料状态；
- 使用人群；
- 人口；
- 使用地区；
- 历史背景；
- 备注。

地区、人口和使用人群应采用可扩展记录结构，为同一阶段的多条地区与年代记录预留空间。

### 8.4 阶段资料状态

| 状态 | 含义 |
|---|---|
| 有记录 | 用户维护较完整的语言数据 |
| 部分记录 | 只存在部分词汇、规则或文本 |
| 无记录 | 仅知道阶段存在，没有语言材料 |
| 重构 | 人工或规则推导的数据；自动历史重构功能暂不进入首版 |

### 8.5 “无记录”阶段

用户将阶段标记为“无记录”后，系统默认只保存基本信息和关系。

可以保存：

- 阶段名称；
- 起止年代；
- 与前后阶段的关系；
- 使用地区、人群等背景；
- 历史事件；
- 缺失原因；
- 备注。

不得自动生成或继承：

- 有效词典；
- 音位表；
- 形态规则；
- 书写系统；
- 可直接用于翻译的数据；
- 假定存在的完整语言状态。

语音学、形态学、词典等页面显示空状态：

> 该阶段被标记为“无记录”，目前没有可用的语言数据。

可提供：

```text
[添加少量已知材料]
[更改资料状态]
[建立人工重构记录]
```

“建立人工重构记录”仅允许用户手工录入或接受 AI 建议，不代表系统具备自动逆向重构能力。

### 8.6 阶段有效状态与词典

差异记录不意味着只有最后阶段拥有完整词典。

每个具有语言数据的阶段在功能上都拥有完整的“有效状态”：

```text
当前阶段有效状态
=
上一阶段有效状态
＋ 当前阶段新增
＋ 当前阶段修改
－ 当前阶段废弃
```

有效状态包括：

- 词典；
- 音系；
- 形态；
- 书写系统；
- 语义；
- 语域；
- 历史形式。

数据库可以保存“继承 + 差异”，界面和功能层必须解析为完整状态。

系统需要统一解析接口：

```text
resolveEffectiveLexicon(stageId)
resolveEffectivePhonology(stageId)
resolveEffectiveMorphology(stageId)
resolveEffectiveWritingSystem(stageId)
```

指定阶段可以正常用于：

- 搜索；
- 翻译；
- 音变；
- 派生；
- 语言接触；
- 词源追踪；
- 与其他阶段比较。

### 8.7 资料可信来源

阶段中的词形、规则和词义应记录来源状态：

- 已确认；
- 规则生成；
- 继承假定；
- AI 推测；
- 人工重构；
- 未知。

词典可提供两种查看方式：

```text
完整工作词典
仅显示已确认内容
```

辅助翻译可提供：

- 严格模式：仅使用已确认内容；
- 辅助模式：允许使用继承、规则生成和人工确认的重构内容。

### 8.8 独立快照

任何阶段或方言都允许转换为独立快照。

适用场景：

- 与上一阶段差异较大；
- 用户导入了完整历史词典；
- 需要独立编辑；
- 不希望上游修改继续传播；
- 需要稳定归档。

操作名称：

> 将当前阶段转换为独立快照

执行后：

- 当前有效状态完整保存；
- 保留历史关系；
- 上游后续修改不再自动传播；
- 仍可手动同步变化。

### 8.9 方言

支持两种方言模式。

#### 轻量方言

保存相对于某个阶段的差异：

- 发音差异；
- 音系规则差异；
- 少量形态差异；
- 地方词；
- 特有词义；
- 拼写差异；
- 废弃或替换词。

轻量方言在功能上也拥有完整有效状态，可以用于：

- 翻译；
- 搜索；
- 造词；
- 派生；
- 语言接触；
- 音变预览。

#### 独立方言语言

当方言拥有大量独立规则、词汇、阶段或后代时，可以：

> 提升为独立语言

提升后保留原有继承、词源和方言关系。

#### 正向演化

用户可以从任意具有有效语言数据的状态或阶段出发：

```text
选择源状态
→ 设置音变和其他演化规则
→ 运行预览
→ 检查词形、同音和规则冲突
→ 选择输出类型
→ 用户确认
```

输出类型：

1. 创建同一 Language 的下一个阶段；
2. 更新已经存在的后续阶段；
3. 创建新的后代 Language；
4. 创建轻量方言；
5. 创建独立方言语言；
6. 仅保存演化方案。

创建下一阶段时允许：

- 自主命名；
- 设置年代；
- 设置资料状态；
- 选择完整生成或仅保存部分变化；
- 选择继承范围；
- 排除专有名词或特殊词；
- 处理冲突。

源阶段始终保持不变。

#### 无记录阶段限制

无记录阶段：

- 不能直接作为严格演化起点；
- 不能自动生成中间词典；
- 可以保留为时间轴节点；
- 可以从更早有数据阶段直接推演到更晚阶段；
- 可以在后续手工补充资料后改变状态。

#### 冲突处理

需要单独的冲突处理页面，显示：

- 源词形；
- 目标词形；
- 冲突类型；
- 已存在词条；
- 同音词；
- 非法形式；
- 用户处理选项。

处理选项：

```text
保留现有词
使用新词
合并为多义词
创建同形异义词
手工修改
跳过
```

#### 逆向历史重构

自动逆向历史重构暂不进入首版开发。

原因：

- 音变通常不可逆；
- 合流、脱落和弱化会造成多种历史候选；
- 自动结果难以保证可靠性；
- 需要姐妹语言、同源词、古拼写等额外证据。

Phase 1.5 只预留入口：

```text
历史重构（后续版本）
```

入口应显示说明，不提供可执行按钮，不得让用户误以为首版已支持该能力。

用户仍可：

- 手工创建早期阶段；
- 手工录入重构数据；
- 让 AI 提出讨论性建议；
- 将人工确认内容标记为“重构”。

AI 可以在需要时检索当前页面之外的信息，但必须保持当前任务优先。

### 10.2 上下文范围

侧边栏顶部显示：

```text

● 当前页面
○ 当前语言
○ 相关语言
○ 整个项目
```

另提供：

```text

```

默认行为：

> 当前页面 + 当前语言必要信息。

### 10.3 分层上下文

```text
第一层：当前页面与当前选择对象
第二层：当前语言与当前阶段
第三层：父语言、子语言、姐妹语言、接触语言
第四层：项目全局语言与历史事件
```

只有在当前信息不足时，才逐层扩大检索范围。

### 10.4 Context Broker

LLM 不直接读取数据库，应通过受限工具获取信息：

```text
get_current_context
get_language_summary
get_language_stage
search_lexemes
get_related_languages
get_etymology_chain
get_historical_events
search_project
```

Context Broker 负责：

- 限制一次读取量；
- 区分语言和阶段；
- 记录调用内容；
- 防止读取敏感设置；
- 控制只读权限；
- 提供审计记录。

### 10.5 引用与可见性

AI 回答应显示本次使用的数据范围，例如：

```text
本次参考：
· 阿兰语 · 诸王时期音系
· 圣典时代词典
· 北方贸易接触事件
· 3 个相关借词条目
```

### 10.6 修改权限

AI 对整个项目默认只有只读权限。

不得直接：

- 修改词典；
- 删除语言；
- 应用音变；
- 合并词条；
- 创建语言关系；
- 修改其他语言；
- 提交批量操作。

涉及修改时生成提案卡片：

```text
AI 提案
→ 应用到草稿
→ 规则验证
→ 用户点击保存
```

## 11. 开发者工具

### 11.1 入口

放置于：

```text
工具 → 开发者工具
```

不放入普通语言导航栏。

### 11.2 安全脚本工作台

默认提供受限 JavaScript 脚本环境。

脚本不能直接接触：

- SQLite；
- 任意文件系统；
- 网络；
- 系统进程；
- API 密钥。

只能调用 FishTongue 提供的受限 API：

```javascript
const words = await fish.lexicon.query({
  partOfSpeech: "noun",
  stage: "current"
});

for (const word of words) {
  fish.patch.updateLexeme(word.id, {
    tags: [...word.tags, "review-needed"]
  });
}

return fish.patch.preview();
```

执行流程：

```text
运行脚本
→ 生成修改补丁
→ 数据验证
→ 差异预览
→ 用户确认
→ 事务提交
```

### 11.3 脚本范围

执行前必须选择：

- 当前词条；
- 当前选择项；
- 当前阶段；
- 当前语言；
- 指定语言；
- 整个项目。

默认范围为当前阶段，不能默认整个项目。

### 11.4 必要安全机制

- 提交前自动创建项目快照；
- 只读模式与修改模式分离；
- 差异预览；
- 数据库事务；
- 失败时整体回滚；
- 最大运行时间；
- 最大对象数量；
- 中止按钮；
- 审计日志；
- 不允许直接执行 SQL；
- 不允许绕过版本与冲突检查。

差异预览示例：

```text
新增：32 项
修改：145 项
删除：0 项
冲突：4 项
警告：7 项
```

### 11.5 高级不安全模式

高级本机代码执行可以作为后续扩展。

若后续启用，必须：

- 在设置中手动开启；
- 显示明确风险；
- 逐项授权文件、网络与进程权限；
- 每次执行高权限脚本再次确认。

Phase 1.5 只需为高级模式预留设置入口，不要求实现。

### 11.6 AI 与脚本

AI 可以辅助生成和解释脚本，但不能直接执行。

```text
用户描述需求
→ AI 生成脚本
→ 用户检查
→ 只读试运行
→ 差异预览
→ 用户确认执行
```

所有 AI 生成脚本显示：

> AI 生成代码，请在执行前检查。

## 17. 验收标准

Phase 1.5 完成后，应满足：

1. 应用不再呈现网页落地页式视觉。
2. 项目和语言操作均在统一桌面框架中完成。
3. 不再出现 `tauri.localhost` 浏览器原生提示框。
4. 用户可以明确区分项目、语言、语言阶段和方言。
5. Language 可以不创建任何用户可见阶段。
6. 用户可以自由命名阶段。
7. 无记录阶段只显示基本信息，不生成语言数据。
8. 任意有数据阶段都可以呈现完整有效词典和规则状态。
9. 用户可以从当前阶段正向创建下一阶段、后代语言或方言。
10. 自动逆向历史重构只显示为后续功能，不进入首版执行流程。
11. AI 默认聚焦当前页面，但可以按需检索相关语言或整个项目。
12. AI 只能生成提案，正式提交由用户完成。
13. 开发者工具脚本默认运行在受限、可预览、可回滚环境。
14. 中英文界面结构一致。
15. 1360 × 860 最小窗口下导航、主工作区和 AI 侧栏均可完整操作。
16. 所有批量修改和冲突操作都有预览、验证和确认步骤。

## 18. 最终产品交互原则

FishTongue Phase 1.5 统一遵循以下原则：

```text
系统组织信息
规则引擎验证
AI 提出建议
用户编辑草稿
用户最终确认
```

对于历史阶段、方言和演化：

```text
Language 可以没有显式阶段
阶段由用户自由命名
有数据阶段可完整使用
无记录阶段只保存已知背景
轻量方言继承并覆盖差异
正向演化创建阶段、方言或后代语言
逆向历史重构暂缓至后续版本
```

对于 AI 和开发者工具：

```text
允许读取必要的项目上下文
默认聚焦当前页面与当前语言
所有修改先形成提案或补丁
验证、预览、确认后才能写入正式数据
```
