# Phase 1.5 交互精修与问题修复报告

## 结论

`emil-design-eng` 阶段已完成。精修严格沿用 FishTongue 设计系统 1.1.0，没有新增竞争性颜色、字体、圆角、阴影或动效令牌。

本轮修复了人工审查提出的浅色表格和折叠导航问题，并重做了窗口拖动调用边界。同时补齐菜单键盘控制、模态框焦点管理、按钮按压反馈和减少动效支持。下一步可以进入 `web-design-guidelines` 最终验收。

## Before / After

| 项目 | Before | After | 原因 |
| --- | --- | --- | --- |
| 浅色表格 | 旧全局隔行样式覆盖新页面，数据行显示为深灰底 | 表头和单元格明确使用语义背景、文字、边框令牌；悬停状态作用到单元格 | 保证浅色、深色主题互不污染 |
| 标题栏拖动 | 指针事件细节值不稳定，标题子元素也可能截获命中 | 标题子元素不接收指针；桌面 Adapter 使用 Tauri 官方 `isTauri()` 和 `startDragging()` | 让整个标题中心区域形成一致的原生拖动入口 |
| 折叠导航 | 48px 模式仍出现纵向和横向滚动条，图标轨道显得拥挤 | 固定 48px 图标轨道、居中图标和展开按钮、隐藏滚动条视觉 | 保留导航能力，同时降低小空间噪声 |
| 按钮反馈 | 多数按钮只有悬停反馈 | 增加令牌化按压缩放和颜色过渡 | 让桌面操作产生即时、克制的触觉感 |
| 开关动画 | 通过位置属性移动圆点 | 改用 `transform` | 减少布局计算，运动更稳定 |
| 顶部菜单 | 基础点击可用，键盘路径不完整 | 支持 Alt 激活、方向键移动、Home/End、Escape 关闭和焦点返回 | 符合桌面菜单使用习惯 |
| 模态框 | 打开和关闭时焦点去向不确定 | 初始焦点、Tab 焦点陷阱、Escape 关闭、触发点焦点返回 | 避免键盘用户丢失当前位置 |
| 模态反馈 | 瞬时出现 | 使用既定时长和缓动进行轻微透明度、缩放过渡 | 建立层级变化，同时避免夸张动画 |

| --- | --- |

| 小窗口与 AI 侧栏 | 依据主工作区实际宽度重排阶段、表单、词典和多栏页面 |
