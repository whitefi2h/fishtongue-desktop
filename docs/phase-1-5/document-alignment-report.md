## 保留且不冲突的技术路线

- Tauri 2 承担桌面、文件、数据库、菜单和 Sidecar 生命周期。
- Next.js/React 只做静态前端，不增加 API Routes、SSR、Server Actions 或 Node 服务。
- 数据链路继续是 `UI → Service → Repository → Tauri SQL Plugin → SQLite`。
- SQLite 仍是项目正式数据的唯一权威来源。
- `.fishtongue` 的保存、迁移、备份和恢复继续遵守“最后一个可用文件不得损坏”。
- Lexurgy 继续使用 Kotlin/JVM Sidecar，不重写规则语言或音变核心。
- AI 和批量操作不能绕过审核直接修改正式数据。
- 一个窗口一次只打开一个项目。

## 实施时必须区分的状态

设计方案同时描述了 Phase 1.5 P0、P1 原型和 P2 入口。开发与文案必须使用以下
状态，避免把路线图写成功能清单：

| 状态 | 用户可期待的行为 |
| --- | --- |
| 已实现 | 可以真实保存、重新打开并通过验收 |
| 可交互原型 | 可以体验页面流程，但不承诺真实业务结果 |
| 预留入口 | 只能查看说明，不能执行 |
| 后续阶段 | 当前界面不应暗示已经可用 |

## 尚未定义、不能自行猜测的接口

以下内容在设计方案中出现，但尚无可实施的数据或协议规范：

- `.fishtongue` 之外的语言交换格式及版本兼容表；
- CSV 字段、编码、重复项和回滚规则；
- 快速开始所用现实语言模板的数据来源、许可证和版本；
- 阶段有效状态的数据库 Schema、差异合并和冲突算法；
- 安全 JavaScript 运行时、资源限额和受限 API 的完整契约；
- AI Provider、Context Broker 工具参数、审计保留期和隐私设置。

这些项目可以先做入口、页面骨架或接口 Port；在补充规范和测试前，不得实现猜测性
数据写入，也不得在 README 中宣称可用。

1. `docs/phase-1-5-ui-ux-design-spec.md`：产品信息架构、UI/UX、交互和功能入口。
